# Yeni Arayüz (Menü Paneli ve Akış Penceresi) Uygulama Planı

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Panelin ve pencerenin yerine Apple çizgisinde yeni bir arayüz koymak:
- Panelde seni bekleyen session önde durur, her satırda bir konu şeridi bulunur.
- Pencerede konular noktalı bir tuval üzerinde soldan sağa akar. Sapaklar dal olarak açılır, kapanınca ana hatta geri döner.
- Pencerede bir adım listesi, kamera ve mini harita bulunur.

**Architecture:**
- **Saf mantık `RadarCore`'da, test edilerek yazılır:**
  - Haiku'nun döndürdüğü `from` (sapak) bilgisi,
  - dal ve hat yerleşimi (`flowLayout`),
  - kamera sınırı ve sığdırma hesapları,
  - bekleme başlangıcı.
- **`SessionRadar` hedefinde görünümler yeniden yazılır:**
  - ortak tema ve cam yüzeyi (`Theme.swift`),
  - panel (`PanelView.swift`),
  - tuval (`FlowCanvas.swift`),
  - pencere iskeleti ve adım listesi (`SessionWindow.swift`).

**Tech Stack:** Swift 6.4, SwiftPM, SwiftUI (`MenuBarExtra`, `NavigationSplitView`, `.inspector`, `Canvas`, `glassEffect`), Swift Testing. Üçüncü taraf bağımlılık yok.

**Spec:** `docs/superpowers/specs/2026-10-23-native-ui-design.md` (onaylanan taslaklar: `docs/superpowers/specs/mockups/`)

## Global Constraints

- **Derleme:**
  - `RadarCore` yalnızca `Foundation` import eder.
  - Swift 6 dil modu kullanılır, derleme uyarısız olmalı.
  - Üçüncü taraf paket eklenmez.
  - Paketin desteklediği en eski sürüm `.macOS(.v14)` olarak kalır.
- **Liquid Glass:**
  - Yalnızca `if #available(macOS 26, *)` içinde kullanılır.
  - Daha eski sürümde aynı yüzeyde `.regularMaterial` kullanılır.
  - Derleme macOS 26+ SDK gerektirir (makinede SDK 27 var).
- **Haiku çağrıları:**
  - Yalnızca mevcut `runAsk` yoluyla yapılır.
  - Yeni bir çağrı türü eklenmez.
  - `from` bilgisi mevcut gruplama çağrısıyla gelir.

  - ✨ ikonu,

### Task 2: Akış yerleşimi ve kamera hesapları

**Files:**
- Create: `Sources/RadarCore/FlowLayout.swift`
- Test: `Tests/RadarCoreTests/FlowLayoutTests.swift`

**Interfaces:**
- Consumes: `Topic` (Task 1'in `from` alanı). Task 1 ile paralel yürütüldüğü için bu görev de `Topic`'e aynı alanı aynı imzayla ekleyebilir: `public var from: Int?`, init'te `from: Int? = nil` en sonda. Birleştirmede tek tanım kalır.
- Produces:

  ```swift
  public struct FlowNode: Equatable, Sendable {
      public var topicId: Int
      public var column: Int      // 0'dan başlar; konuların ilk isteğine göre sıra
      public var lane: Int        // 0 ana hat; -1, -2 yukarı; +1, +2 aşağı
      public var parent: Int?     // lane != 0 iken dalın ayrıldığı konunun id'si
  }
  public func flowLayout(_ topics: [Topic]) -> [FlowNode]

  /// ekran = dünya * scale + (x, y)
  public struct Camera: Equatable, Sendable {
      public var x: Double; public var y: Double; public var scale: Double
      public init(x: Double, y: Double, scale: Double)
  }
  public let cameraScaleRange: ClosedRange<Double>        // 0.4...2.0
  public func clampCamera(_ c: Camera, content: CGRect, viewport: CGSize) -> Camera
  public func fitCamera(content: CGRect, viewport: CGSize, padding: Double = 40) -> Camera
  public func focusCamera(on rect: CGRect, scale: Double, viewport: CGSize) -> Camera
  public func resolveTopicSelection(_ selected: Int?, topics: [Topic]) -> Int?
  ```

**Yerleşim kuralları** (testler bunları sabitler):
1. Konular `requests.min()` değerine göre sıralanır. `column` bu sıradaki indekstir.
2. `from` geçerliyse, yani Task 1'deki üç koşul tutuyorsa, ve konu `done` değilse konu hattın dışındadır. Diğer bütün konular `lane = 0` olur.
3. Hattın dışındaki bir konunun ebeveyni de hattın dışındaysa (ebeveynin lane'i L), konu aynı tarafta bir şerit daha uzağa yerleşir: `lane = L + L.signum()`.
4. Diğer hat dışı konular, sırayla yukarı ve aşağı dönüşümlü yerleşir: ilki -1, ikincisi +1, üçüncüsü -1, …
5. Hat dışı konularda `parent = from` olur. Hattaki konularda `parent = nil`.

**Kamera kuralları:**
- `clampCamera`:
  - Önce `scale` değeri `cameraScaleRange` içine çekilir.
  - Sonra görünen alanın dünya koordinatlarındaki merkezi, `((viewport.w/2 - x)/scale, (viewport.h/2 - y)/scale)`, `content` dikdörtgeninin içine sıkıştırılır. `x` ve `y` buna göre yeniden hesaplanır.
- `fitCamera`:
  - `scale = min(1, max(0.4, min((w - 2p)/content.w, (h - 2p)/content.h)))`.
  - `content` görünen alanın ortasına gelir.
- `focusCamera`: Verilen dikdörtgenin merkezi görünen alanın merkezine gelir. `scale` değeri aralığa çekilir.
- `resolveTopicSelection`: Seçili id listede varsa o döner. Yoksa `state == "active"` olan konunun id'si, o da yoksa son konunun id'si döner. Liste boşsa `nil` döner.

- [ ] **Step 1: Failing testler**
  - `flowLayoutMainLineAndBranches`:
    - Girdi:
      - 1 `done` (istekler [1]),
      - 2 `open` (`from: 1`, istekler [2]),
      - 3 `done` (`from: 1`, istekler [3]),
      - 4 `active` (istekler [4]).
    - Beklenen (`topicId`, `column`, `lane`, `parent`): `(1,0,0,nil)`, `(2,1,-1,1)`, `(3,2,0,nil)`, `(4,3,0,nil)`.
  - `flowLayoutAlternatesSides`: Hattın dışında kalan iki bağımsız konu sırayla `-1` ve `+1` şeridine yerleşir.
  - `flowLayoutNestsOnSameSide`: Ebeveyni `-1` şeridinde olan hat dışı bir konu `-2` şeridine yerleşir.
  - `flowLayoutIgnoresInvalidFrom`: `from` değeri 99, konunun kendisi ya da kendisinden sonra başlayan bir konu olduğunda `lane == 0` ve `parent == nil` olur.
  - `flowLayoutSortsByFirstRequest`: Sırasız gelen girdide `column`, `requests.min()` sırasına göre verilir.
  - `flowLayoutEmpty`: `flowLayout([]) == []`.
  - `clampCameraKeepsCenterInsideContent`:

    - Beklenen: sonuç `x == 400`, `y == 300 - 200 == 100` olur. Merkez x 0'a, y 200'e sıkışır.
  - `clampCameraClampsScale`: `scale` 5 ise 2.0'a, 0.1 ise 0.4'e çekilir.
  - `fitCameraClampsMinScale`:
    - 4000×200'lük içerik ve 800×600'lük görünen alan için `scale == 0.4`.

  - `focusCameraCentersRect`:
    - Girdi: dikdörtgen (500,100,200,60), `scale` 1, görünen alan 800×600.
